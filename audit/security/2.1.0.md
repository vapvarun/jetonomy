# Security review: Jetonomy 2.1.0

Scope: everything shipped since v2.0.7, Free and Pro (Free about 150 files, Pro about 88 files of own code). Main
risk surfaces: the new space-moderator ban setting, settings writes through `\Jetonomy\Settings` (REST
`/admin/settings` and `wp jetonomy config set`), hide-online-status, sidebar widgets and space cards, the
`\Jetonomy\Queue` scheduler and its SQL on Action Scheduler tables, uninstall, Pro private attachments served
through a gated route (including PDF thumbnails), webhook private-space opt-in and the 2.0.7 delivery conversion,
badges, poll result timing, private profile fields, announcements, web push and digests.

Verdict: nothing HIGH or above is reachable by any member role, a role without `read`, a signed-out visitor or a
space moderator. Nothing blocks the release. Three LOW items are recorded below.

## G1 mechanical sweep

`security-sweep.sh --baseline v2.0.7`. No CRITICAL patterns in either plugin.

- Free: `sql-direct-interpolated` 136 to 134, `nonce-only-auth` unchanged at 44, `esc-sql-on-nonscalar` 0 to 1,
  `no-abspath-guard` 23 to 40, REST routes 89 to 90.
  - `esc_sql()` in `includes/db/migrations/class-migration_1_7_0.php:55`: escapes column names taken from the
    migration's own fixed spec list (identifiers cannot be bound). Scalars, never request data.
  - The 17 extra unguarded files are CLI tools under `bin/` (`check-never-fatal.php`, `check-pot-fresh.php`,
    `check-script-translations.php`, `bin/lib/extension-guard-check*.php`). `bin/` is not in the release zip.
- Pro: `sql-direct-interpolated` 30 to 45, `no-abspath-guard` 6 to 17, REST routes 61 to 64.
  - New interpolated SQL interpolates only table names or `intval`-cast id lists: web-push model
    (`implode( ',', array_map( 'intval', ... ) )`), badge and poll cleanup, uninstall `IN ({$in})` built from
    `intval` action ids, and the QA harness.
  - The 11 extra unguarded files are internal tooling under `docs/plans/`, which is not tracked for release and
    not in the zip.

## G2 authorisation

`RouteAuthorityTest` (Free) and `RouteAuthorityProTest` run in the unit and combo suites and pass.

Gate E reachability, on the combo install: 152 GET dispatches over every `jetonomy/v1` and `jetonomy-pro/v1`
route, as an administrator and as a signed-out visitor. No 5xx, and every route has a `permission_callback`.
Routes that stream a file and exit were excluded.

Space-moderator ban (new, off by default), confirmed at runtime as a space moderator with Subscriber site role and
the setting forced on for the request only:

| Attempt | Result |
|---|---|
| Ban the space owner | 403 `jetonomy_cannot_ban_space_staff` |
| Ban a site administrator | 403 `jetonomy_cannot_ban_admin` |
| Ban someone not in the space | 404 `jetonomy_not_space_member` |
| `global_ban`, or `silence` with a `space_id` | 403 |
| `space_ban` in a space they do not moderate | 403 |
| Lift a site-wide ban, or another space's ban | 403 |
| `GET /moderation/ban` (site-wide list) | 403 |
| Ban a member of their own space, then lift it | 201, then 200 (intended) |

Every test row was removed afterwards.

Pro, runtime:
- `/attachments/files`, `/attachments/batch` and `DELETE /attachments/files/{id}` return 401 signed out and 403 to
  a Subscriber.
- `GET /webhooks` returns 401/403 to both.
- Badge delete, restore, award and revoke return 401/403.
- A temporary owner-only profile field was visible to its owner and the admin, and hidden from a visitor and from
  another Subscriber.

## G3 reviewed diff

The diffs were read hunk by hunk against the lowest-role threat model. Checked and safe:

- **Settings** (`/admin/settings` GET and POST): `manage_options` (a Subscriber gets 403).
  - Only keys in `Settings::schema()` are written, after schema validation and the form sanitizer.
  - Secrets are masked; a masked value sent back keeps the stored one.
  - `moderators_can_ban` and role/capability keys save only for `manage_options`.
  - Email From is sanitised, so no header injection.
- **Hide online status:** every REST path exposing `last_seen` goes through `is_online()`, and the leaderboard is
  shaped per viewer after the shared cache.
- **Sidebar widgets and space cards:**
  - Trending uses the space-visibility SQL with a per-viewer cache key.
  - Popular Tags counts only visible posts.
  - Widget ids are allow-listed before a partial path is built.
  - Follow renders only after `can( read )`.
  - All output is escaped.
- **Sitemap:** 404 unless the community is public.
- **`includes/class-queue.php`:** every query on the Action Scheduler tables is prepared with matching
  placeholders. The compare-and-set cancels are single `UPDATE ... WHERE status = pending AND claim_id = 0`.
- **Pro attachments:**
  - Download runs `viewer_can_read_link()` and answers 404 to a caller who cannot read. `?size=` only picks a named
    size of the same attachment. Only images and PDFs are served inline, with `nosniff`.
  - Attach checks ownership and readability, then re-runs upload validation (`wp_check_filetype_and_ext` plus
    finfo, SVG excluded).
  - Writes stay inside `realpath( uploads/jetonomy )`.
- **Pro webhooks:**
  - The private-space filter applies once in `fire()`; `include_private` is written explicitly, default off.
  - SSRF is blocked by `wp_http_validate_url` on save and `wp_safe_remote_post` on send.
  - On upgrade, 2.0.7 deliveries (URL and secret in their args) are converted. Then every row of the old hook is
    deleted in any status (`retired_jobs()` -> `Queue::delete_rows()`), re-queued until none is left; Pro QA UG12
    asserts zero rows.
- **Pro polls, announcements, AI held reason, web push, digests:**
  - Result timing blanks counts in the only payload builder.
  - Announcements re-check each recipient can read.
  - The held reason shows only on moderation views.
  - Push endpoints are checked by `Url_Guard` on subscribe and send.
  - Digest content selection is unchanged.
- **Uninstall (both):** `WP_UNINSTALL_PLUGIN` guard; prepared `esc_like` patterns; ids `intval`-cast.

## Findings

- **LOW (in 2.0.7 too, not new): a space admin can space-ban the space owner or a fellow space admin.**
  - Where: `includes/models/class-restriction.php` `actor_may_restrict()`. The roster check runs for a space
    moderator only; a space admin with no site capability falls through to the site rules, which stop self,
    administrators and site moderators but nothing space-level.
  - Impact: a promoted space admin can lock the owner out of their own space until a site moderator lifts the ban.
  - Fix proposal (Bugs card): refuse a target who is the space author (unless the actor is), and optionally a
    target whose space role is `admin`.
- **LOW (new with gated private files): a member's REST nonce rides in private-space file URLs.**
  - Where: Pro `includes/extensions/attachments/class-rest.php` (gated URL builder).
  - A nonce does not authenticate on its own, but a member who shares a private file link hands out a `wp_rest`
    nonce valid for up to 24 hours. That nonce could be used to forge a REST request from that member's own browser.
  - Fix proposal (Bugs card): send `Referrer-Policy: no-referrer` from `download()`, and move inline links to a
    short-lived signed token instead of the REST nonce.
- **LOW (informational, intended): a user with `moderate_comments` (Editor and above) can attach any validated
  media-library item to a post they can read.** That is the trust intended for the role.

A reviewer flagged "2.0.7 webhook secrets stay in Action Scheduler rows after the upgrade". This was checked and
is not the case: see Pro webhooks above.

## Scanner-visible but safe

- Interpolated SQL in models, migrations, recount, purge and the CLI: table names from `\Jetonomy\table()` or
  `$wpdb->prefix` and fixed column lists; values go through `prepare()`, or are `intval`-cast id lists.
- `check_ajax_referer()` hits: each Jetonomy AJAX handler checks `current_user_can()` right after.
- `POST /moderation/ban` and `DELETE /moderation/ban/{id}` use `auth_mutation( 'read' )`: the handlers decide
  (`issue_error()` / `lift_error()`), confirmed above, and `audit/route-authority.json` declares it.
- The search highlighter's `phpcs:ignore` output escapes every segment.
- Pro `readfile()` in attachment download: the path is `get_attached_file()` of the stored link's attachment id,
  served only after the viewer check. `echo` of the service worker is static JavaScript.

## Not blocking, recorded

- Carried from 2.0.7: the 23 Free / 6 Pro class files without a direct-access guard (declare classes only).
- WP Vanguard scan (G4): not run in this prep pass; run it against the release-candidate site before tagging.
