# Jetonomy — JS Internationalization Rule (1.4.3+)

## The Rule

**Every user-facing string in JavaScript is translatable. Never inline an
English literal.** Which mechanism depends on how the script is loaded:

| JS context | Translate with | Notes |
|---|---|---|
| Classic scripts (`wp_register_script` / `wp_enqueue_script`): admin-common.js and every `admin-*.js`, composer, header, modals, login block, icon picker, pagination, setup wizard, media grid, lib/optimistic | `wp.i18n.__` / `_n` / `_x` / `sprintf`, domain `jetonomy` | Add `wp-i18n` to the handle's dependencies and call `\Jetonomy\script_translations( $handle )` after registering it. |
| Script modules (view.js, connect-app.js, pagination-hydrator.js) | `state.i18n.<key>` (Interactivity state from `class-template-loader.php`) or `window.jetonomyData.i18n.<key>` for helpers outside the store | Modules cannot take script translations, so PHP supplies the translated strings. |
| Any context, string containing an owner-configured label (space / topic / reply / member noun) | A PHP-localized key built with `sprintf()` + `jetonomy_label()` / `space_label()` | JS cannot know the configured noun. Keep these keys in PHP even in classic scripts (header `hcStatsFormat`, composer `joinSpaceFailed`, setup wizard `fillCategoryAndSpace`). |

Translator comments go immediately before the call (`/* translators: %s: ... */`),
and every count uses `_n()`, never a number concatenated with a fixed plural.
Shared msgids must carry one identical translator comment everywhere, or
`wp i18n make-pot` warns.

## Module fallbacks

In script modules, a PHP key may still carry an English fallback so the JS
works if the bridge fails (embeds that localize a reduced payload). The
fallback must be the exact PHP string for that key, rendered with the default
nouns where the PHP string takes a label:

```js
button.textContent = state.i18n?.cancel || 'Cancel';
```

## JSON translation files

`grunt i18n` (release step) runs `wp i18n make-json`, which writes one
`languages/jetonomy-{locale}-{md5}.json` per JS source file. WP-CLI strips
`/.min.js$/` with unescaped dots, so a source named `*min.js` (e.g. the old
`admin.js`) gets the wrong hash and never loads: do not name a script so its
name ends in `min.js`.

## Enforcement

`@wordpress/no-unlocalized-strings` is configured as **error** (no baseline)
in `.eslintrc.json`. Run `npm run lint:js` before every commit — zero
errors is the gate.

The Pro plugin mirrors this rule against `window.jetonomyProAdmin.i18n` /
the `jetonomy-pro` text domain.
